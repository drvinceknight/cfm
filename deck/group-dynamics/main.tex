\slidehead{Scenario 2}
\notesref{Group dynamics}{A simple framework}

\vspace{0.3cm}

\begin{minipage}[t]{0.44\linewidth}
\vspace{0pt}
{\large
A: ``it runs without an error, so it is correct''.\\[0.6em]
D: ``it is wrong''.\\[0.6em]
\textcolor{inkred}{Ten minutes. Both getting irritated.}}
\end{minipage}
\hfill
\begin{minipage}[t]{0.52\linewidth}
\vspace{0pt}
\ask{Which kind? What do they do right now?}

\answerspace{11.8}{5.6}{%
  \textbf{Fact}, so the easiest kind.\\[0.5em]
  Write a test that separates the two claims, or check the function on a case
  worked out by hand. Running without an error is not the same as being
  correct.}
\end{minipage}

\vspace{0.3cm}

{\large How long should this have taken? \answerblank[6]{About two
minutes}}

\answerspace{11.8}{5.6}{%
  \textbf{Effort.}\\[0.5em]
  The messages put the problem where D cannot answer it and the minutes cannot
  record it. Raise it at the next meeting as an observable fact, and record
  what D agrees to do before the one after.}
\end{minipage}

\slidehead{What is \texttt{self}?}
\notesref{Python for Mathematics, Object oriented programming}{What is the self variable for?}

\vspace{0.4cm}

\begin{minipage}[t]{0.50\linewidth}
\vspace{0pt}
\codebox{11.2}{class Polynomial:\\[0.2em]
\idt def \_\_init\_\_(self, coefficients):\\
\idt\idt self.coefficients = coefficients\\[0.4em]
\idt def degree(self):\\
\idt\idt return len(self.coefficients) - 1}
\end{minipage}
\hfill
\begin{minipage}[t]{0.46\linewidth}
\vspace{0pt}
\ask{\texttt{degree} takes no argument when you call it. So what is
\texttt{self}?}

\answerspace{10.6}{6.0}{%
  The instance it was called on. \texttt{p.degree()} runs
  \texttt{degree} with \texttt{self} set to \texttt{p}.\\[0.5em]
  Python passes it for you, which is why it is in the definition and not in
  the call.}
\end{minipage}

\vspace{0.2cm}

{\small\color{inkgrey} The instance it was called on. Python passes it for
you, which is why it is there in the definition and not in the call.}

\newpage
\slidehead{Does your project need a class?}
\notesref{Python for Mathematics, Object oriented programming}{Define a class}

\vspace{1.3cm}

\begin{center}
{\LARGE\bfseries\color{inkred} No.}
\end{center}

\vspace{1.0cm}

\begin{center}
{\LARGE A library of plain functions is a perfectly good library, and it
is marked the same way.}
\end{center}

\vspace{1.2cm}

\ask{So when is a class worth it?}

\vspace{0.4em}

\begin{center}
\answerspace{22}{3.4}{%
  When several functions keep passing the same things around. A class bundles
  that data with what you do to it. If your functions do not do that, plain
  functions are the simpler library.}
\end{center}

\newpage
\slidehead{Out of the notebook}
\notesref{Python for Mathematics, Using a command line and an editor}{Run python code in a file}

\vspace{0.5cm}

\begin{minipage}[t]{0.46\linewidth}
\vspace{0pt}
\codebox{9.8}{cd project\\ ls\\ python main.py}
\end{minipage}
\hfill
\begin{minipage}[t]{0.50\linewidth}
\vspace{0pt}
\ask{You hand in a \texttt{.py} file, not a notebook. Why?}

\answerspace{11.4}{5.8}{%
  Because the \texttt{.py} file \emph{is} the library. A notebook does not
  provide a library, it imports one.\\[0.5em]
  And so the tests and doctests can run against it, from a terminal:
  \texttt{python test\_<library>.py} and
  \texttt{python -m doctest README.md}.}
\end{minipage}

\vspace{0.3cm}

{\small\color{inkgrey} \texttt{cd} moves, \texttt{ls} looks, and
\texttt{python main.py} runs a file. The library is the file; a notebook is
one of the places that imports it.}
